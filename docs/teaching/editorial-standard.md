# 电子教材的成书标准

目标是完整的传统图形学基础教材。当前逐章建设；文件存在、测试通过或页面能打开，单独一项都不代表一章已经成稿。

## 教材叙述与用语

正文以定义、条件、推导、例子和结论展开。句子的主语优先使用所讨论的对象，例如“屏幕重心坐标”“单位法线”或“该参数化”；说明全书约定用“本书”，说明局部模型用“本节”或“本例”。避免连续使用“你”“我们”“咱们”串联讲解，不以问答聊天代替论证。

保持清楚、自然的语言，不追求公文式表达。用于实验的“拖动”“观察”“比较”“计算”可直接作为指令，随后指出比较对象和预期关系。设问用于提出学习问题，不在每个段落中重复设问并自答。称呼统一为“读者”，无需在各段重复称呼。

章节标题说明概念或学习问题；公式前先给出符号、空间、单位与适用条件，公式后解释几何或计算含义。图示说明应指出图元和变量的对应关系，避免“看一眼就懂”“很神奇”等评价。保留必要直观类比，但应立即回到可检验的数学对象。

术语首次出现时给出规范中文与必要英文，后续保持一致。避免把“相机”和“观察视口”、“像素”和“样本”、“法线”和“单位法线”等不同概念混称。代码变量名、界面名称和数学符号分别按其实际含义引用。

正文不叙述开发过程，不使用“本轮新增”“后面再补”“已经接入”等项目进度表达。实现限制作为模型适用范围说明；待开发功能与检查进度放入规划或验证文档。编辑时逐段核对公式、代码、演示位置和前后承接，不能只通过删除人称完成润色。

## 读者完成一章后应得到什么

每章围绕一个具体成像问题，明确前置知识、可以解释的现象、可以推导的关系、可以修改的 Python 函数。正文给出符号与坐标约定、逐步推导、至少一个手算例子、一个边界或错误反例、适量的编程练习和下章如何使用本章结果；练习和演示数量服从概念需要，不固定每章两道或两幅。

数学需要“够用的桥”：使用矩阵前解释基；使用投影矩阵前推相似三角形；使用面积权重前解释有向面积；使用采样定理前先展示连续信号与样本为什么能混淆。长推导可以分层阅读，但不得用动画代替必要的论证。

## 电子书应带来的能力

- 画面、参数、符号与 Python 中间量描述同一状态，读者能追踪一个点或像素。
- 预设可以复现正常情况和错误情况；比较图共用相机、范围、颜色映射与无关参数。
- 读者可以暂停、点选、改数值、逐步检查；需要时提供拖动与采样动画。默认不持续消耗计算资源。
- 正文与源码之间不靠复制粘贴维护。展示实际核心文件；复杂算法按小函数拆解，避免先教框架。
- 章内定位、全书目录、前后章衔接、专注阅读与本机位置恢复服务于长时间阅读。位置恢复不冒充学习掌握度。
- 插图各有解释任务；几何示意与具体计算结果区分，配图可追溯到来源或生成代码。

## 发布前逐章审查

| 审查 | 必须看到的证据 |
| --- | --- |
| 内容与来源 | 原始资料的相关段落确实支持引用；教学文字是原创组织；约定不同处已经说明。 |
| 数学 | 手算、独立推导或独立参考方法；性质测试覆盖关键不变量与边界，不能只重复实现。 |
| 代码 | 核心可单独调用；变量含义与形状清楚；测试和练习命令可以运行；错误输入有解释。 |
| 交互 | 实际浏览器操作关键控件、点击/拖动、预设、暂停和恢复；读数与图像一致。 |
| 可读性 | 正文、行内/独立公式、表格、图片、代码都经过视觉检查；桌面与窄屏无被裁掉的关键控件。 |
| 章节联系 | 前置章已经给出所需概念；后续章实际复用相同约定或算法；能走完一个连续学习路径。 |
| 运行 | 轻量 uv 环境可复现；本机启动与部署入口分别验证；在线发布不依赖开发者机器上的文件路径。 |

全书还需整体验证：当前已有章节及后续新增内容形成连贯主线；用统一场景比较光栅化与光追；数学补充、术语与符号能检索；练习从理解走向迁移；长时间浏览不会积累后台动画或会话状态串用。未验证的项如实留在验收记录里。

## 本轮视觉与交互方向

视觉：接近纸张的浅底、深绿文字、克制的分隔、中文正文与数学自然并排。结构：实验先回答问题，随后是阅读路线、推导、实际源码与练习，章末回到全书。交互：拖动产生即时因果反馈，逐步检查揭示算法顺序，导航与收起实验帮助专注阅读；动效只在解释变化时出现。

渲染与操作界面须单独验收，不能以数学测试通过或无页面溢出代替。当前主画面、参数层级、字体与窄屏重排仍待按[设计审查](../planning/renderer-design.md)实施，演示保持嵌在相关正文中。
