# 可交互教材 · 章节、排版与交互

本书以 GAMES101 的完整知识范围为最低基线，再增加可操作的数学解释、可读 Python 实现和数值实验。当前已有十二个可运行章节，属于全书的第一批内容；不能据此宣称已经覆盖全部课程。建设范围见 [全书路线](../../ROADMAP.md)，逐项缺口见 [GAMES101 覆盖表](../planning/games101-coverage.md)，现有功能与验证范围见 [场景探索验收](../verification/exploration-upgrade.md)。

书页是学习的主线。学生在推导附近直接操作演示，再展开实际源码；章节栏可以收起。实验不移到独立工作台，也不依靠额外的练习模式或资料导航组织阅读。

## 覆盖与完成的标准

覆盖按知识点判断，不能把一个章节标题、一处引用或一张效果图计作已经讲授。每个知识点应形成下面这些相互对应的内容，深度与它在课程中的地位相称。

| 要求 | 学生实际能做什么 |
| --- | --- |
| 问题与前置 | 知道正在解决什么问题、已有方法为何不足，以及需要哪些已学概念；操作前能作一个可检验的预测。 |
| 数学与条件 | 解释变量、空间、单位、数组形状与适用条件；沿几何或概率关系得到公式，并用小例子核对。 |
| 书内真实交互 | 直接改变与问题有关的点、物体、相机、光源、样本或时间，看到计算结果随之变化；能暂停、比较并恢复。 |
| Python 与中间量 | 找到实际运行的短函数，沿输入追到输出；画面、公式和探针呈现同一计算中的权重、深度、方向、贡献或误差。 |
| 独立性质验证 | 用手算、已知解析解、另一条计算路径或关键不变量检查结果，同时解释一个边界或失败情形。 |
| 原创、来源与复现 | 讲解和实验自行组织，在相关论断处引用具体资料；给出运行命令、必要参数与随机种子，使读者能重现并修改实验。 |

“已验收”表示这一组内容已经共同检查过。只有正文，没有算法或可操作结果，仍有未完成项；代码运行成功也不能代替数学、教学顺序和实际浏览器体验的检查。测试应验证性质与结果，避免把实现逐行改写成期望值。

状态按同一知识点逐项记录，并链接已有文件或验证证据：

| 状态 | 含义 |
| --- | --- |
| 规划 | 问题、先修、模型范围和计划中的演示已明确，尚不表示内容已实现。 |
| 正文 | 原创解释、变量约定、必要推导、例子与来源已写出。 |
| 算法 | Python 核心可独立运行，能产生教学所需的结果和中间量，已有独立检查。 |
| 交互 | 实际算法已接入书页，学生能通过操作探索目标关系。 |
| 已验收 | 正文、数学、算法、交互、视觉与章节衔接均有相应证据；仍存在的模型或设备限制已说明。 |

正文和算法可以并行建设，记录时保留各自状态；整个主题的完成度不能由其中最领先的一项代表。章节与演示数量由解释需要决定，不规定每章恰有两个、三个或任何固定数量的演示。

GAMES101 第 18、21、22 讲涉及的概览性质主题，按原课的解释深度覆盖，并配合范围明确的小型 Python 模型。例如，用可改变方向和参数的散射分布理解外观，用可拖动的关节或时间插值理解运动，用受力和积分误差可检查的系统理解模拟。无需为每个概念实现生产级毛发、皮肤、角色或流体系统，但必须说清所保留的因素、忽略的因素及结论的适用范围；静态图片和术语罗列不能替代这些实验。具体知识范围以覆盖表为准，不能用一个简单模型代替整讲中的其他主题。

## 每章的学习闭环

章首说明前置知识、当前问题和可检验目标，章末留下练习、完成标准与后续承接。常用顺序是：

**问题 → 预测 → 操作 → 几何与数值 → 推导 → Python → 新例子验证。**

这个顺序服务于解释，不要求每节机械重复。读者初见现象时，先给足够简单的操作；推导进入新的关系时，再插入聚焦该关系的演示。综合场景用来连接已经建立的概念，不能承担整章所有解释。

每章应让读者能解释现象、手算或推导关系、修改函数并验证变化。图上的点、公式符号、数值字段和 Python 变量使用同一约定。正常例子旁边安排有解释价值的边界或反例，例如非均匀缩放后的法线、重复透视校正或 Nyquist 边界。概率、积分、微分方程等数学在首次需要时搭桥，再由后续章节复用。

练习数量随目标设置，避免用固定题数代替教学设计。现有 `exercises.py` 保留 TODO，参考算法在 `core.py` 等实际实现文件；读者先尝试，再运行自检。书页显示完整源码及高亮，当前不提供任意 Python 在线执行器。

## 排版与导航

当前入口是原生 HTML/CSS/JavaScript 书页，正文连续阅读，演示嵌入段落之间，源码按需展开。章节目录、前后章链接和本章演示跳转服务于阅读；浏览器保存已提交的综合演示参数与侧栏收纳偏好。阅读位置提示不是学习掌握度，也不表示所有演示状态或滚动位置都已持久保存。

正文保持适当行宽、清晰的中文字号与行距，公式、图形和代码各有足够空间。代码使用等宽字体，公式和代码允许局部横向滚动；窄屏不靠缩小整页文字适配。几何符号、量纲与数值说明紧邻需要它们的画面，避免读者反复跨屏寻找定义。

视觉采用克制、准确的科研表达：稳定的排版层级，清楚的坐标、刻度、标注与选中反馈，有限且一致的语义颜色。点、向量、公式项与对应代码变量在必要时联动强调；动效用于揭示变换、构造或因果关系，并允许暂停。不能仅用颜色区分含义，也不靠装饰卡片、重复提示或持续运动制造丰富感。

能够通过操作说明的关系优先做成实时演示。静态图可用于概念总览、历史材料或可下载快照，但不能替代学生应当亲手改变的变量；外部图注明出处，自绘图保留生成方法。

## 交互要求

- **直接操作**：优先在对象所在位置拖点、拾取、移动或旋转；参数面板用于精调与检查。根据数学模型提供有效工具，例如理想球体没有有意义的方向旋转，固定屏幕轮廓的深度实验不应假装支持任意模型变换。
- **连续反馈**：拖动时有持续结果，松手后恢复完整计算精度；耗时与当前预算可辨认。浏览器预览、Python 预览和正式计算的职责明确，不用另一套着色结果冒充正在讲授的算法。
- **同一状态**：几何、公式、辅助线、探针与成像对应同一组输入；阅读、查看源码或放大演示不应悄悄重置实验。迟到的请求不能覆盖已经提交或取消的操作。
- **有意义的对照**：A/B 比较默认只改变研究因素，保持无关的相机、范围、分辨率、颜色映射与随机条件一致。若刻意研究其中一个因素，明确指出它；高采样参考或简化几何也应说明身份。
- **真实中间量**：显示实际样本、重心权重、裁剪点、深度候选或射线路径。像素中心、求值位置和显示范围分别标注，箭头与数值来自真实计算。
- **恢复与自由探索**：支持适合该演示的撤销、恢复、聚焦、缩放和拖动；一次连续手势对应一步编辑。退化输入给出可理解的状态，不留下无解释的空图或 NaN。
- **统一帮助**：基础操作与快捷键收在公共帮助入口。仅在工具受数学约束、状态发生变化或操作失败时给出局部说明，不在每幅演示旁重复长篇指南。

当前数学演示支持缩放、平移、播放、控制点调整及 SVG 导出；综合演示支持对象与相机操作、Python 图像探针、A/B 对照、撤销和布局调整。具体能力按章节与对象区分，不能把一个场景的流畅度或可编辑范围当作全书结论。随机实验在其参数中提供种子和计算预算；不把尚未统一实现的参数导入导出写成现成功能。

## 数学与代码保持一致

公式必须连接到构造及条件。例如透视先从相似三角形推导 `x_screen ∝ f·x/(-z)`，再解释 `w=-z`；不能只给投影矩阵让读者记忆。采用不同空间、方向或颜色约定时显式转换，沿用 [数学与渲染约定](../conventions/rendering.md)。

实现返回必要的教学信息，不只返回彩色图片。正式成像与教学数值由 Python 计算；`teaching_figures.py` 返回数学构造，浏览器用 SVG 呈现；`studio_render.py` 调用章节核心并返回图像、场景几何和探针结果。Canvas 2D 与 WebGL 用于浏览器操作和预览，不替代所教授的 Python 渲染算法。

验证优先检查有解释价值的性质，如射线交平面核对 UV、裁剪面积核对覆盖率、路径贡献之和核对像素、时间步收敛比较积分误差。高采样结果不能无条件称为真值。数值误差、简化假设与性能预算应成为可观察的学习内容，不能被漂亮的图像掩盖。

## 文件与检查入口

| 文件 | 职责 |
| --- | --- |
| 章节 `lesson.md` | 原创正文、推导、手算、练习目标、来源及 `[[demo:id]]` 插入位置。 |
| 章节 `core.py` | 不依赖界面的数学与渲染函数，可单独阅读和调用。 |
| 章节 `exercises.py` / `test_core.py` | 留给读者的实现与自检，以及独立性质、边界和数学算例。 |
| `teaching_figures.py` | 各聚焦演示的 Python 构造、数学读数与参数定义。 |
| `studio_render.py` | 章节参数校验、核心调用、场景数据、图像与中间结果的适配。 |
| `studio.py` | 正文转换、实际源码读取、静态资源及 Python 计算接口。 |
| `web/studio.js` / `web/teaching-figures.js` | 书页装配、交互状态、结果展示及 SVG 演示。 |

正文以独占段落的 `[[demo:id]]` 指定演示位置；已有数学演示的注册与插入机制不限制每章数量。`[[demo:main]]` 接入当前章节的综合演示，现有页面复用一个主场景实例。若教学需要多个独立综合场景，应补足实例隔离与状态能力，再把对应交互标为完成；不能因此删减必要的解释或用静态截图代替。

第 04 章另有 `raster.py` 和顺接的 `raster-lesson.md`；章节按实际需要增加少量清晰文件。跨章算法复用普通函数，避免为了目录扩展引入复杂框架。源码展示实际文件，维持讲解、运行代码与下载内容一致。旧 `app.py`、`lab.py` 属于保留的 Panel 界面，不是当前电子书的装配入口。

从 `graphic/` 运行 `uv run --locked python tools/check.py` 检查数学与接口测试；用 `start.command` 或 `uv run --locked python tools/serve.py` 打开当前教材。验收应实际走过“预测 → 操作 → 数学解释 → 修改 Python → 新例子”，记录桌面、窄屏、键盘与触摸已经检查的范围。环境继续由 uv 管理；公网启动、HTTPS 和部署复现单独验证，不由本机可运行推断已经完成。
