# 综合实践 · 一幅图像，两次可见性计算

本书的各章将成像拆成可以单独研究的问题。本实践把它们重新组合：一张棋盘地面、一根柱体、一个椭球，以及一盏光。目标是沿着一个实际像素，说明它为什么看到这块表面，又为什么处于明处或阴影中。

第一次渲染从光源出发，保存光源所见的最近深度；第二次从观察相机出发，确定可见表面，再把这个表面投回光源的深度图查询。两次渲染复用同一套变换、裁剪、覆盖和深度算法。

## 1 · 从哪里开始读代码

完整入口是 [src/capstone/core.ts](/src/capstone/core.ts)。`capstoneSpec()` 只描述场景，`renderCapstone()` 组合渲染与采样，`inspectCapstone()` 读取实际像素并重新检查光源查询。核心算法仍放在对应章节，不在综合项目里复制一遍。

| 数据流 | 对应实现 | 需要检查的约定 |
| --- | --- | --- |
| 椭球参数 → 顶点与面 | [12 · makeMesh](/src/chapters/12-geometry/core.ts) | 经线闭合，极点不重复；法线来自隐式梯度 |
| 物体 → 世界几何 | [场景组合](/src/render/scenes.ts) | 点使用模型矩阵，法线使用逆转置 |
| 世界 → 齐次裁剪空间 | [03 · lookAt / perspective](/src/chapters/03-camera/core.ts) | 列向量语义，先视图变换再投影 |
| 裁剪 → 像素覆盖 | [04 · raster](/src/chapters/04-barycentric/raster.ts) | 先裁剪再除 w；共享边只归属一次 |
| 片元 → 可见表面 | [11 · renderFrame](/src/chapters/11-pipeline/core.ts) | 深度不做二次校正，普通属性需透视恢复 |
| 世界点 → 光源可见率 | [10 · shadowQuery](/src/chapters/10-shadows/core.ts) | 先比较深度，再平均比较结果 |
| 线性颜色 → 显示像素 | [01 · encodeRgba](/src/chapters/01-pixels/core.ts) | 光照与采样在线性域完成，最后编码 |

算法成像由这些 TypeScript 函数在 Web Worker 内计算。空间视图用 Three.js 提供相机与物体操作；两者共享几何和相机，但空间视图的近似材质不承担教学数值验证。

## 2 · 检查一个像素

在算法图像中点击表面，展开“像素检查”。记录行列、图元编号、世界位置、深度、法线和线性 RGB。背景的图元编号为 −1，不应把背景缓冲中的默认向量当作有效表面。

选中柱体并移动它。先预测哪些量改变，再查看结果：柱体移动可能改变相机的可见表面，也可能只改变地面收到的阴影。移动光源则改变光源投影和入射方向，即使相机的深度与图元编号保持不变，颜色也可以改变。

命令行的 `inspectCapstone()` 还返回实际阴影查询的 UV、当前深度、过滤结果等信息。它使用像素缓冲保存的世界点，重新投影并访问相同的阴影图；数据来源可以沿函数调用逐步追溯。

## 3 · 保持输出尺寸，改变积分精度

超采样的比较必须保持最终尺寸不变。`renderCapstone(state, size, samplesPerAxis)` 在每个像素中放置规则样本，平均线性 RGB 后再编码：

$$
C_{ij}\approx\frac{1}{N^2}\sum_{a=0}^{N-1}\sum_{b=0}^{N-1}C\left(j+\frac{a+1/2}{N},\ i+\frac{b+1/2}{N}\right).
$$

这里 N 是每轴样本数，工作量按 $N^2$ 增加。实现先生成高分辨率内部图像，再按固定块求平均；这一做法与规则子像素位置对应。它不会改变阴影图自身的分辨率，也不自动解决所有高频混叠。

```bash
npm run render -- --size 384 --samples 1
npm run render -- --size 384 --samples 2 --out outputs/capstone-4spp
```

命令输出 `image.ppm` 与 `pixel.json`。PPM 是直接储存 RGB 字节的简单图像格式，可用支持 PPM 的图像工具读取；在线观察和 PNG 导出则在书内完成。探针 JSON 对应最终像素中心的几何与阴影查询，超采样图像则平均整个像素内的多个样本，两者需要区分。

## 4 · 三项独立检查

1. **可见性与提交次序。** 保持几何与相机不动，设置 `state.params.reverse = true`，比较深度测试下的输出。非平局像素应不变；深度完全相等时应按严格小于规则保留先到者。
2. **阴影偏移与过滤。** 将 PCF 改为硬阴影，再逐渐增加偏移。辨认自遮挡与接触阴影脱离的不同表现。PCF 平滑深度比较的结果，并没有模拟面光源。
3. **线性域与显示域。** 对同一组样本，分别平均线性值和显示编码值。用[第 01 章](?chapter=pixels)的黑白各半手算作为独立参照，不能仅凭画面“看起来平滑”判断正确性。

`src/capstone/core.test.ts` 检查实际像素回读、提交次序，以及固定输出尺寸的线性平均。运行 `npm test` 可复现这些检查；它们证明所列性质，不能替代对任意场景的数值分析。

## 5 · 本实践的边界

场景使用不透明三角形、有限分辨率阴影图、简单局部光照和规则超采样。椭球仍由网格近似，光源范围有限，偏移需要结合尺度解释。本实践没有实现全局光照、真实镜头或动画系统。

能够从输入几何追到一个像素，并说明每一步的空间、单位、近似与误差来源，才算完成了这条传统渲染主线。[数学补充](?appendix=math)和[术语索引](?appendix=glossary)可用于再次核对全书约定。
