# 09 · 纹理作为函数：方向与位置

[第 08 章](?chapter=textures)先用 UV 查询颜色，再让纹理表示高度和法线。这些实验有一个共同结构：给定一个地址，返回一个值。地址可以是表面 UV，也可以是一个空间方向，甚至直接是一点的三维位置；值也可以由图片读取，也可以通过函数直接求得。

本章先用镜面球研究方向查询：相机转动时，反射方向改变，球面上的环境映像随之移动。随后用程序纹理研究位置求值：同一空间函数采用物体坐标或世界坐标作为输入，会产生不同的纹理运动。这两个实验将纹理从二维图像查询推广到方向与位置上的函数。

先修是[第 02 章](?chapter=transforms)的向量与变换、[第 03 章](?chapter=camera)的相机、[第 07 章](?chapter=lighting)的法线，以及[第 08 章](?chapter=textures)的双线性查询。数学会在用到时出现：球坐标解释全景图，点积构造反射，平滑插值连接格点值，有限求和叠加不同尺度。本章不要求完整的光线追踪知识；本章用球面网格提供可见表面与插值法线，[第 15 章](?chapter=rays)会进一步拆解求交与递归传播。

## 8 · 把地址、函数和数值结果连起来

回顾三个不同的查询。图像纹理先得到表面 UV，再在离散数组中重建颜色；环境纹理先得到方向，再转成全景或立方体地址；程序纹理直接把位置送入一个确定性函数。它们都可以用于着色，但输入空间、边界和近似并不相同。

| 查询 | 输入 | 本章实际做的事 |
| --- | --- | --- |
| 镜面环境 | 世界反射方向，经环境旋转转入局部方向 | 查经纬图、立方体图，或直接算同一个连续环境函数 |
| 格点噪声 | 二维或三维位置 | 找邻近格点，以平滑权重组合可重复的伪随机值 |
| 多尺度合成 | 同一位置的不同频率版本 | 用有限项和及幅度归一化控制细节 |

在 `core.ts` 中按 `directionToLatlong → sampleLatlong` 阅读环境查询；反射方向由[第 15 章](?chapter=rays)的 `reflect()` 计算，组合成像位于 `src/render/render-study.ts`。在 `procedural.ts` 中从格点、权重和单次求值读起，再看多尺度合成。`figures.ts` 将这些输入输出组织为书内演示。

主演示由 TypeScript 光栅器找到球面网格的可见点，恢复法线并计算反射方向，再查询选定的环境表示。空间视图用于编辑场景，算法成像用于比较环境映像；两侧共享实际相机。点击像素可以读取世界位置和法线，方向与地址的细节见前面的聚焦实验。

在 `exercises.ts` 中完成两道小题：把一个单位方向换成经纬图地址，再把已经计算好的多个尺度值做归一化加权。两题分别对应本章的两条主线，不要求先重写整幅图像。

```bash
npm run exercise -- 09
```

自查时可以问：为什么全景图最左、最右要互相作为邻居？为什么六个立方面中的同一方向不需要先转成球面经纬度？为什么每次查询调用随机数生成器会让纹理闪烁？为什么能计算任意坐标的函数仍会在像素采样后混叠？回答时应给出具体方向、格点或频率作为依据。

下一章[第 10 章](?chapter=shadows)把查询对象换成光源看到的深度。存进纹理的数不再直接作为颜色，而是先与表面深度比较，得到可见性。这里建立的“输入空间、数据含义、查询规则”三件事会再次用到。
